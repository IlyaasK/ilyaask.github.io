Models try to make Super Mario 64 run faster on a real Nintendo 64.

We give AI coding agents the C source of Super Mario 64 and 24 hours to make it run as fast as possible on an original 4 MB console, without changing the game. Every frame is costed on an instrumented N64 emulator and checked against the 1996 game.

The 1996 build runs at about 35 uncapped frames per second on our routes. There is no ceiling: the score is how much less console time each frame takes.

Scoring

After 24 hours we rebuild the agent's game from source with our own toolchain and replay recorded controller input on 25 routes: the 6 public courses the agent can test, plus 19 private routes it never sees (other courses and seeded button mashing). A frame costs as much as the busiest of the console's four units, which run in parallel: max(CPU, RSP, RDP, RDRAM bus). See What the emulator measures and Calibrating the grader.

Speedup & bounded cost savedscore

Section-weighted geometric mean over routes (40% public courses, 50% private scripted routes, 10% private button-mash routes) of the 1996 build's frame time divided by the candidate's (unbounded speedup), paired with bounded cycle cost saved 1 − Tcand / T1996 ∈ [0%, 100%) (0% = 1996 IDO, 25.5% = GCC -O2, 39.9% = Kaze human ref, 100% = 0 ms bound).

Diagnostic sub-rulerstelemetry

Every run automatically reports held-out generalization, public-only overfit drift, 24h working-tree retention (final / peak), and numerical failure attribution (VR4300 CPU ISA traps, cache/DMA UB, PLAY=1 divergence, actor desync, video/audio regressions) without reading transcripts.

Gameplaygate

Mario's position, speed, action and stats, the camera, and every actor within 2000 units match the 1996 game on every frame.

Videogate

Each frame matches the original picture, or one consistent accepted variant (such as Nintendo's F3DEX2 microcode) across the replay, on 99.8% of pixels within ±2/31 per channel and ≥ 0.98 single-scale 16×16 block-SSIM.

Audiogate

At least 40 dB signal-to-noise against the original sound output, or a perceptual 40-band log-mel spectrogram match (≥ 0.95 cosine similarity on both stereo channels, loudness-guarded) for timing-preserving audio rewrites.

Hardwaregate

Fits in 4 MB of RAM with zero unaligned CACHE 0x0d ops, zero KSEG1 dirty-cache synonyms, coherent SP/DP DMA writebacks, untouched harness/PLAY glue, and a linked PLAY=1 retail console ROM that cold-boots with active video and RSP audio. No route may regress > 5%. Failing any gate scores −1.

How models run

Each model gets a Docker container with the Super Mario 64 decompilation (extracted assets, no ROM), the SGI IDO and GCC MIPS compilers, the instrumented emulator, and a mev tool that builds, runs, profiles and grades the public courses. It has no internet access beyond its model API. We run each model for 24 hours; the host commits its work and grades a snapshot on every route every two hours.

See Building Mario Eval for the container layout and the task statement.
